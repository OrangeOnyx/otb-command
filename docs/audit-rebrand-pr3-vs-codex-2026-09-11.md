## Part C — Decision frame

**Option 1 — Merge PR #3 now; Codex later as its own PR (recommended).**
Identity lands today on the real product line; Codex's genuinely good work
(auth fail-closed, store scoping, evidence flow, isolation) comes in after the
seven fixes, with the data edit split into its own reviewed commit.

**Option 2 — Merge PR #3, cherry-pick Codex's backend only** (`api/_seed-auth`,
gated endpoints, `state-storage`, isolation tooling). Lowest UX risk, keeps the
A-2 workspace on the preview until the design ruling.

**Option 3 — Adopt Codex as master.** Not advisable until the two blockers and
the SOT question are closed; it would also drop PR #1/#2 work unless merged
(clean merge confirmed, but the A-1 wording/north changes then collide with
REV 14 conventions).

**Operator rulings needed (three):**
1. Design system: keep plan-room, or adopt the 04C type/palette app-wide?
2. Rent roll: are the 2026-09-09/10 confirmations the new Tier-1 for 143 / 145 /
   119 / 139 / 141 / 117.5 / 119.5? If yes, CLAUDE.md facts + SOT docs change.
3. Home sheet: D-1 or A-2, for both roles.

**Confidence & Caveats:** High on the code findings (each verified against the
worktree or a render); medium on data-provenance since the owner confirmations
Codex cites are not in the repo — only its summary of them is.
