## F-1 · Invoices + late fees → full parity

Design. An invoice is a per-unit, per-month document over the append-only
ledger: the month's `charge` + `late_fee` + `nsf` + `adjustment` debits.
Number = `INV-YYYYMM-<unit>` (matches the AC convention, deterministic, so
regeneration is idempotent). State lives in a NEW typed table
`invoices` (content tier like `governance_items`): `id` (the number), `unit`,
`ym`, `amount`, `entry_ids jsonb`, `status` check `draft|sent|void`,
`sent_on`, `sent_via`, `notes`, stamps. **Paid is derived, never stored**:
`invoicePaid(model, entries)` = FIFO payments cover the invoice's charges
(reuse `fifoOpenDebits`). Void = every underlying charge voided.
Render = branded printable HTML (`src/lib/invoice.js` → `invoiceHTML`) with
`<title>INV-…</title>` so Save-as-PDF names the file; "PDF render" is the
browser print path (no server PDF exists — keep it that way).

Files. `src/lib/invoice.js` (pure: `invoiceModel`, `invoiceNumber`,
`invoiceStatus`, `invoiceHTML`), `src/lib/invoiceUI.js` (drawer panel:
month picker, ⤓ Invoice, Mark sent, status chip; owner read-only),
`src/lib/remote.js` (list/upsert invoices), migration
`supabase/migrations/20260911120000_invoices.sql`, `docs/phase-b/assert-suite.sql`
(operator write / owner read / tenant own-unit read / vendor+stranger blind),
`src/views/drawer.js` mount, `src/views/maintenance.js` tenant face shows
"Invoices" read-only list, `src/styles.css`, `test/invoice.test.mjs`.

## F-2 · CAM reconciliation → per-tenant shares + statements

Design. Two data additions, one engine upgrade, one printable.
1. `src/data/recovery-terms.json` — per-unit structured recovery terms
   transcribed from the AC lease abstracts (`docs/harvest/ac-archive-2026-08-29/
   lease_abstractions.json`, `keyClausesSummary`): `{ capPct, capBasis:
   "prior_year_actuals", capFromLeaseYear: 2, capComponents: ["cam","tax","ins"],
   auditRights, baseYear: null, source }`. 14 units carry caps (143 = 4%, the
   rest 5%); no base-year clause exists anywhere → `baseYear` null everywhere
   with a validator that accepts a future value. `_note` records provenance.
2. `financials.opexYears` — optional `{ "YYYY": {taxes,…} }` map inside the
   existing `financials` singleton (layer_settings) so prior-year actuals exist.
   Validators in `store.applySnapshot` + `layers.test` keep the six-line shape.
3. `camrecon.js`: `reconModel` gains `year`, `priorOpex`, `terms`; per unit
   emits `share`, `actualShare`, `cappedShare` (min(actualShare,
   priorShare×(1+cap)) when cap applies and prior exists, else null + reason),
   `billed`, `trueUp` (= (cappedShare ?? actualShare) − billed), `capApplied`,
   `capReason`. Gross-up: default factor from `calc/grossup.js` on CAM only
   (actual occupancy = occupied SF / GLA, target 95%); operator `grossUpPct`
   stays as an override. `reconCaveats()` shrinks to what is still unmodeled
   (base-year stop; prior-year actuals when absent) — update the test.
4. `src/lib/camstatement.js` — per-tenant annual CAM/Tax/Ins reconciliation
   statement (branded, tenant palette, PSF breakdown per CLAUDE.md rule,
   estimates paid vs actual share vs cap vs amount due/credit, methodology
   paragraph from `grossUp().methodology`).
UI: P-1 recon card gets a year picker, prior-year opex inputs (opexYears),
per-tenant rows with true-up and a ⤓ Statement chip per row.
Files: `camrecon.js`, `camstatement.js`, `financial.js`, `layers.js` (shape),
`store.js` (validator), `recovery-terms.json` (+ loader/validator in store),
`test/camrecon.test.mjs`, `test/camstatement.test.mjs`, `test/layers.test.mjs`.

## F-3 · Board + stakeholder reports → variants

Design. `boardReportModel(quarter, briefModels, { audience, extras })` and
`boardReportHTML(model, opts)` gain `audience ∈ board|lender|stakeholder`.
Same engine, same stored briefs; variants change section selection, headings
and disclosures. `extras` is optional live data fetched by `openBoardReport`
(payment_history rows → `payHistoryStats`; ledger aging via
`listPortfolioLedger`) so lender gets a collections/aging block. Debt service
and member/distribution data do not exist → both variants print an explicit
"not on file" line (never a zero). Lender = occupancy trend, rent roll totals,
NOI, expirations 12–24 mo, collections + aging, debt "not on file".
Stakeholder = NOI, indicative value, occupancy, leasing position, actions,
distributions "not on file". S-1 card gets three chips: ⤓ Board · ⤓ Lender
· ⤓ Stakeholder. Extract the duplicated OO CSS into `src/lib/docbrand.js`
(exported consts) and import it from both `brief.js` and `boardreport.js`.
Files: `boardreport.js`, `docbrand.js`, `brief.js` (import only),
`safe.js`, `test/boardreport.test.mjs`.

## F-4 · HVAC → PM contract tracking + T-1 deadlines

Design. NEW typed table `hvac_contracts` (content tier, `stamp_layer_row`):
`id`, `unit`, `vendor_id`, `scope`, `frequency` check
`monthly|quarterly|semiannual|annual`, `starts_on`, `ends_on`, `last_service_on`,
`status` check `active|lapsed|ended`, `ref` (e.g. "§9.01"), `notes`, stamps.
Next due is DERIVED: `nextDue(contract)` = last_service_on + frequency (or
starts_on when never serviced). `src/lib/hvac.js` mirrors `governance.js`
exactly (vocab, validators, id gen `hvac:<unit>:<n>`, `hvacDeadlines()` fold
with the same 30-day grace shape, cache trio, refresh, add/update/delete,
`logService(id, date)`), plus `listHvacUnits()` so the 28 imported
`hvac_units` rows finally reach the app. T-1: import, `Promise.all`, forEach
emitting `{d,c,t,sub}` "HVAC PM due — <unit> · <vendor> (<ref>)". Drawer HVAC
block: system rows from `hvac_units` (fallback hvac.json split text), the
contract line with next-due + "Log service" + "Add contract" (operator only;
149 prefill button "From §9.01: monthly · Butcher Air"). No seed rows —
the covenant fact stays in facts.js; the contract row is operator-entered.
Files: migration `20260911130000_hvac_contracts.sql`, `hvac.js`, `dates.js`,
`drawer.js`, `remote.js` (hvac_units read), assert-suite, `styles.css`,
`test/hvac.test.mjs`.
