# 05 — Data Model

System code: **OTBC**. Two data layers exist and must be understood together:

- **Layer A — app runtime data** (`src/data/*.json`): the projection the Vite app
  renders. Regenerated by tools from upstream sources; some hand-maintained.
- **Layer B — Source of Truth** (`docs/sot-2026-07/*.csv`): the owner-corrected
  signed rent roll, adopted 2026-07-16, a proper relational star schema with an
  explicit authority ranking. Authoritative over Layer A for tenant/economics/
  expirations.
- **Layer C — live server state** (Supabase): persisted layers + append-only
  event/money tables (see 08-technical-architecture.md).

All VERIFIED by direct file reads unless noted.

## Entity catalog

### OTBC-ENTITY-001 · Property (`docs/sot-2026-07/properties.csv`, 1 row)
Fields: `property_id` (PK, `prop_on_the_boulevard`), `property_name`,
`ownership_entity`, `property_type` (`retail_strip_center`), `market`,
`primary_address`, `total_rentable_sf` (62,810), `source_of_truth_status`,
`notes`. Root of the hierarchy.

### OTBC-ENTITY-002 · Unit — app form (`src/data/units.json`, 27 records)
| Field | Type | Req | Notes |
|---|---|---|---|
| unit | string | PK | includes fractional (`117.5`, `119.5`) and letter splits (`135A/135B`) |
| dba | string | y | `"VACANT"` for vacant |
| legal | string | opt | legal entity; empty for vacant |
| use | string | y | free text |
| cat | enum | y | retail, food, services, financial, medical, office, vacant |
| status | enum | y | active, vacant, owner, anchor |
| base / total | number | y | PSF annual; 0 for vacant/owner |
| monthly | number | y | **TOTAL monthly $** (base+additional — operator convention) |
| start / end | YYYY-MM-DD | y | empty for vacant + owner-occupied |
| notes | string | opt | |
| sf | number | y | rentable SF |

Calculated: `monthly ≈ total × sf / 12` with two owner-accepted stated-rent
exceptions (Pink Paisley 101/103 −$4.84; Cat Clinic 119.5 +$0.01) that must NOT
be "fixed". Combined leases (101/103, 115/117, 125/127, 139/141) carry
**reporting allocations**, not standalone legal charges.

`units.public.json` = redacted 1:1 mirror (drops legal, base, total, monthly,
notes) — the only unit data in the public JS bundle; the rest hydrates via
auth-gated `/api/seed` (C1 split).

### OTBC-ENTITY-003 · Unit — SOT form (`units.csv`, 27 rows)
`unit_id` (PK) · `property_id` FK · `building_id` · `unit_label` (`117 1/2`
format!) · `rentable_sf` · `current_status` (ACTIVE/VACANT/OWNER_OCCUPIED) ·
`current_tenant_id` FK · `current_lease_id` FK · `lease_suite_group` ·
`is_split_from_combined_lease` bool · `allocation_percent_of_lease_group` ·
`allocated_monthly_reporting_amount` · `source_authority` · `notes`.
The hub table joining units→tenants→leases.

### OTBC-ENTITY-004 · Tenant (`tenants.csv`, 22 rows)
`tenant_id` PK · `display_name` · `legal_entity` · `dba` · `status` ·
`primary_contact_id` (dangling FK — contacts table not shipped) ·
`billing_address` · `source_authority`.

### OTBC-ENTITY-005 · Lease (`leases.csv`, 21 rows) — economics authority
`lease_id` PK · `property_id`, `tenant_id` FKs · `lease_suite_group` ·
`lease_status` · `rentable_sf` (group-level) · `base_psf`, `cam_psf`,
`tax_psf`, `insurance_psf`, `total_psf` · `monthly_rent_stated` (billing
authority) · `monthly_rent_formula_check` (audit calc) · `monthly_variance` ·
`expiration_date` · `source_authority` · `notes` · `doorloop_dates_ignored`
(all True). One row per suite group; combined-lease economics live here.

### OTBC-ENTITY-006 · LeaseUnit junction (`lease_units.csv`, 25 rows)
`lease_unit_id` PK · `lease_id`, `unit_id` FKs · `unit_label`, `unit_sf`,
`lease_suite_group`, `allocation_percent`, `allocated_monthly_reporting_amount`,
`allocation_is_legal_charge` (False for combined groups — key rule), `notes`.
27 units minus 2 vacants.

### OTBC-ENTITY-007 · RecurringCharge (`recurring_charges.csv`, 105 rows)
`charge_id` PK · `lease_id` FK · `charge_type` (base_rent, cam,
tax_reimbursement, insurance_reimbursement, total_monthly_authoritative) ·
`amount_type` (annual_psf | monthly_stated) · `annual_psf` ·
`monthly_amount_formula` · `monthly_amount_calculated` · `billing_frequency` ·
`source_authority` · `notes`. Exactly 5 per lease; the
`total_monthly_authoritative` row is the billing figure.

### OTBC-ENTITY-008 · LeaseClause (`lease_clauses.csv`, 21 rows)
`lease_clause_id` PK · `lease_id` FK · `use_clause` ·
`exclusive_or_prohibited_uses` · `insurance_requirement` · `late_fee_terms` ·
`payment_method` · `hvac_split` · `maintenance_repairs` · `source_authority`.
Data quality: literal string `"true"` as missing-value artifact in several
rows; mostly-blank HVAC template strings.

### OTBC-ENTITY-009 · Recoveries (`src/data/recoveries.json`)
Per-unit `{base, cam, tax, ins, total}` PSF + `camFlatPsf` (2.1). Invariant
`base+cam+tax+ins == total`. **Single source for CAM/Tax/Ins** (units.json
supplies base/total only — enforced in rentroll.js).

### OTBC-ENTITY-010 · Compliance schema (`src/data/compliance.json`)
11 fields (coi, lic, hvac, grease, ansul, dep, w9, walk, sign, lease, ach),
`foodOnly` = [grease, ansul], states enum `u|ok|flag|na` + labels, seed for
unit 149. Cell **states** live in the store `comp` layer, not this file.

### OTBC-ENTITY-011 · Vendor (`src/data/vendors.json`, ~70; mirrored to `public.vendors`)
`id` slug PK · `company` · `contact` · `email` · `phone` · `city` · `notes` ·
`kind` (service | payee | person). Supabase adds `active`, `coi_expires`,
`coi_note` (COI tracking migration). Email presence = portal-capable.

### OTBC-ENTITY-012 · Directory (`src/data/directory.json`)
`propertyContacts[]` (`pc:*` — role/company/name/phone/email/note, 7 entries),
`propertyDocuments[]` (`pd:*` — name/type/ref/link/note, ~20; type enum
Marketing/Report/Survey/Entitlement/Easement/Operations/Source of truth/Title/
Analysis/Reference/Floor plan), `unitDocTypes[]` (6 controlled strings).
A document **register** (pointers), not a blob store.

### OTBC-ENTITY-013 · HVAC split (`src/data/hvac.json`)
Per unit: `repair` / `replace` (formatted **strings**: `"$1,500"`, `"50%"`,
`"100%"`) + `tier` (standard | pct | full); null for vacants. Provider Butcher
Air Conditioning. Parsing hazard: money-as-string.

### OTBC-ENTITY-014 · Geometry (`src/data/geometry.json`, REV 12)
The plat-traced site model: `demising` (two buildings, bay widths with
provenance strings), `liquorLine` (§3a church-easement arc), `parking`
(9 zones, `totalPlat` 314, `variance {99-11797, 324/344}`, reconciliation
note), `streets`, `easements`, `boundary` (main tract + remote Lot 7 Block M),
`layers` (SVG primitive draw list), `units` (unit → {x,y,w,h} plan-px rects),
`viewBox`. The A-1 rendering authority and the legal-geometry record.

### OTBC-ENTITY-015 · Spatial cluster
- `heights.json` — unit → feet (real CAD BLD_HT matches; 22/27 = 16.4′).
- `footprints-geo.json` — GeoJSON FeatureCollection, 27 unit polygons + `georef`
  affine block (anchorCad/anchorLL/azY/scaleTweak).
- `sat-base.json` — frozen Esri z19 composite corners for MapLibre.
- `splat-align.json` — quaternion/scale/position aligning the 3DGS splat to
  Lens-B world (+fit metadata).

### OTBC-ENTITY-016 · Camera registry (`src/data/cameras.json`)
17 cameras: `id, name, ip (10.10.10.x), dwViewId (UUID), suite (unit FK),
pos{x,y} (plan px), aimDeg, fovDeg, rangePx, zone, posConfidence` + `excluded[]`
(4 off-property) + cloud metadata (DW Spectrum system "Belle Reality").

### OTBC-ENTITY-017 · Parking occupancy cluster
- `docs/c3-stall-zones.json` — per-camera stall quads in native camera px
  (~34 stalls, 7-8 cams), authored + validated.
- `src/data/stall-map.json` — stall-id → {rank: row56|lot8|field-149|
  aisle-101|north-edge, index, confidence, ada?} (33 stalls; est-geometric ±1
  pending operator stall walk).
- Supabase `occupancy_samples` — append-only, PK (frame, stall), written only
  via secret-gated `post_occupancy_samples`.

### OTBC-ENTITY-018 · Link registries (per-unit Drive pointers)
`lease-links.json` (25 units — tenant/file/G:-path/Drive url; combined leases
share files; 121 marked Draft) · `logo-links.json` (24) · `logo-thumbs.json`
(generated manifest, 25) · `floorplan-links.json` (all 27; 101/103 have url2) ·
`contacts-info.json` (unit → {name,email,phone}; email coverage ~16%).
Confidential registries ride in `api/_seed.json`, not the public bundle.

### OTBC-ENTITY-019 · Persisted client layers (store, `lib/layers.js` registry)
Nine layers, localStorage + `property_state` JSONB mirror: `comp` (compliance
cell states), `notes`, `actions` (board overrides {lane, edit, dismissed,
custom[]}), `contacts`/`documents` (collection overrides {edit, dismissed,
custom[]}), `financials` ({opex{6 lines}, capRatePct}), `ownerSheets` (id

### OTBC-ENTITY-020 · Server tables (Supabase — see security-model.sql)
`profiles` (id, email, role) · `authorized_emails` · `property_state`
(property_id, layer, data jsonb, updated_at) · `vendors` (+coi cols) ·
`vendor_log`, `safe_log` (audit) · `chat_threads` (+trigger_source unique) /
`chat_messages` · `api_usage` (email, kind, day, n) · `app_secrets` (deny-all)

### OTBC-ENTITY-021 · Governance tables (SOT pack)
`source_authorities.csv` (rank 1 signed rent roll → 2 all-units → 3 lease
abstracts → 99 DoorLoop never) · `validation_rules.csv` (5 rules incl. blocking
`unit_sf_total_must_equal_62810`, `doorloop_dates_cannot_override…`) ·
`known_exceptions.csv` (the two stated-rent variances + required system
behavior: "store both, bill the stated amount"). **This authority-ranked,
exception-logged SOT pattern is itself a reusable asset.**

## Relationship map

```
Property ─┬─ Unit(SOT) ── unit_label ↔ unit ── Unit(app) ── units.public (redacted)
          │     ├─ current_tenant_id → Tenant
          │     └─ current_lease_id  → Lease ─┬─ LeaseUnit (junction, allocations)
          │                                   ├─ RecurringCharge (5/lease)
          │                                   └─ LeaseClause
          ├─ Geometry.units / footprints-geo / heights / floorplan-links (by unit)
          ├─ recoveries / hvac / contacts-info / lease-links / logo-* (by unit)
          ├─ Camera → suite(unit); Camera → c3-stall-zones → stall-map → Geometry.parking
          ├─ Directory (property contacts + doc register) · Vendor (↔ public.vendors)
          └─ Server: property_state(layer) · compliance_events(unit,field) ·
             ledger_entries(unit) · occupancy_samples(stall) · chat_threads/messages
```

Recommended keys for a rebuild: surrogate UUID PKs everywhere; natural keys
(`unit_label`, vendor slug) as unique columns; `org_id`/`property_id` FKs on all
rows; junction table for lease↔unit (already correct in the SOT).

## Duplicates, gaps, normalization problems, migration risks

1. **Headline RSF conflict**: SOT blocking rule says 62,810; audit GLA is
   62,883 (headline vs demised sum — documented as a labeled convention, but a
   rebuild must carry both figures explicitly or one report will be "wrong").
2. **Unit-label format drift**: `117 1/2` (CSV) vs `117.5` (JSON) vs `135A` —
   any CSV↔JSON join needs a normalizer.
3. **Combined-lease dual representation**: per-unit `monthly` in units.json are
   reporting allocations; only the CSV layer marks `allocation_is_legal_charge`.
   A naive consumer of units.json would bill allocations. Carry the flag into
   the app model on rebuild.
4. **Money-as-string** in hvac.json; literal `"true"` artifacts in
   lease_clauses.csv; vendor city-casing/typos (`Prairiville`; probable dup
   `Investar` vs `Investart` Bank).
5. **Dangling FK**: tenants.primary_contact_id → contacts table not shipped
   (app uses contacts-info.json keyed by unit instead).
6. **Missing entities vs a full PM system**: work orders, invoices, POs,
   inspections, incidents, budgets, delinquency status (partially via ledger
   aging), CAM reconciliation records, insurance policies (COI dates exist on
   vendors only, not tenants), amendments (history lives in prose notes).
7. **Coverage gaps**: contacts email ~16%; deposits missing for 107/137/143/149
   (open SOT item); parking Δ −10 deliberately unreconciled.
8. **Migration risk**: `property_state` JSONB layers are schema-free — the
   layer registry (`lib/layers.js`) is the only schema. Porting requires
   formalizing each layer's shape (this document + layers.js suffice).
