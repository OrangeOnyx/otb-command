## Use a template

Open a file under `templates/` in a browser and choose System, Light or Dark. Edit its HTML in any text editor. Replace bracketed prompts with verified content. Copy `assets/`, `tokens/`, `templates/styles.css` and `templates/theme.js` with the template, preserving relative paths.

The templates are layout starters, not deployed websites or a full JavaScript component library. Example buttons are marked as visual examples. Do not ship them as working actions without implementation and acceptance testing. Reports and proposals use browser print styling; decks have a 16:9 print rule. No operating data, forms service or analytics are connected.

## Rebuild

Python 3.10 or later, no environment variables or credentials:

```text
python -m pip install -r source/requirements.txt
python source/build.py
```

The build regenerates PDF, Markdown, CSS, application SVG plates, offline HTML and application starters. It checks contrast first and fails if declared pairs do not meet their thresholds. After a source change, visually review PDF pages and browser output before issuing a release. Regenerate the manifest using `python source/package.py`; the archive is created beside this folder.

Font files are already bundled. `fonttools` is not required for rebuild because static font instances are included. Assets are never fetched by the generator. Fonts were obtained from the Google Fonts repository on 2026-09-20; licenses accompany each family.

## Scope and limitations

This package defines the new Cypress Command design direction. It has not migrated or published an existing website or product. Logos preserve the original vector geometry with approved new colors. The master reference boards contain illustrative metrics and imagery, not verified operational records or licensed production photography. No claim of PDF accessibility certification or complete WCAG product conformance is made; the machine checks cover declared color pairs. Full implementation must also satisfy keyboard, semantic, responsive and content requirements in the guide.

## Accessibility and print

Reference: [WCAG 2.2](https://www.w3.org/TR/WCAG22/). Source Terra and Mustard are not safe small-text colors on every Paper surface; use `action-text` and `warning-text`. Decorative `rule` is not a control boundary. Consult the contrast matrix rather than guessing.

Hex/RGB are authoritative sRGB values. No universal CMYK or Pantone equivalence is claimed. For commercial print, convert using the printer's specified ICC profile, stock and process, then approve a physical proof. The guide is a digital reference PDF with embedded fonts, not a bleed-ready production print job.

## Version 1.1: fuller color and purposeful depth

All four color families now have explicit `brand-*-surface`, `brand-*-strong` and `on-brand-*` roles for editorial expression. Operational success/warning/danger roles remain separate. There is no fixed 80% neutral rule. Use color for meaningful regions and keep long-form reading and dense data readable.

Shadows are explicitly supported at three levels: flat reading surfaces, softly raised interactive/grouped surfaces, and floating menus/overlays. Theme-aware `--cc-shadow-raised` and `--cc-shadow-floating` aliases resolve to the correct light/dark shadows. The portal demonstrates each level live. The eight starters now show expanded color use.

The portal supports section search, mobile navigation, current-section highlighting, theme-aware color inspection/copy, elevation selection and a local form-state demonstration. Clipboard fallback selects the value if browser permissions prevent copying. The demo does not store or transmit entries.

Use this exact tagline for the company. Treat prior slogans in supplied reference images as historical examples, not competing approved taglines. Reuse the same mapping within an artifact instead of alternating colors for decoration. The existing palette, typography, logo geometry and elevation system remain in place.
