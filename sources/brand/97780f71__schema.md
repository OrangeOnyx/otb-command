# Token schema: cypress-command-tokens/1.0.0

This is a project-specific JSON schema convention, not a DTCG-format assertion.

- `schema`: required schema name/version string.
- `version`: release version string.
- `colorSpace`: `sRGB`.
- `palette`: original source primitive hex values, using role-like keys for traceability. Prefer themes for application styling.
- `themes`: `light` and `dark`, each containing the identical set of semantic role keys and exact six-digit hex strings. All values are resolved, so no alias resolver is necessary.
- `scales`: each named item has `value`, `type`, and `unit`. Dimensions are px or pt; durations are ms; number/string/fontFamily/shadow use an empty unit. Append unit to value for CSS.

Color role `foo` becomes `--cc-color-foo`; scale `foo` becomes `--cc-foo`. A `type-*-family` value such as `serif` refers to the `font-serif` scale. Set CSS `font-family: var(--cc-font-serif)` rather than using the symbolic value directly. Line-height values are explicit dimensions, not unitless multipliers.

Use `action` for fills and large accents; `action-text` for small links on canvas/surface. Use `warning` for indicators, `warning-text` for small labels. Use `danger-text` for textual errors and `danger` for error fills. `on-action` and `on-danger` are foregrounds only for their respective fills. `rule` is decorative; `control-border` defines necessary input boundaries. Semantic tinted surfaces use `text` body copy.

Disabled foregrounds retain readable contrast as a system quality choice. Contrast checks are based on adjacent solid sRGB pairs; opacity, photographs and gradients require separate evaluation. Dark danger pressed retains the base fill and adds a 2px inset on-danger line so label contrast remains intact.

Theme and expression are independent: theme maps color; expression maps hierarchy and density. Never implement Editorial / Technical / Archival / Digital as four unrelated palettes.

## Additive roles in release 1.1.0

`brand-terra`, `brand-olive`, `brand-mustard`, `brand-oxblood` identify expressive families. Their `-surface` values are soft fields with `text` foreground. Their `-strong` values pair with the corresponding `on-brand-*` foreground. Strong light Mustard requires white #FFFFFF rather than Paper. These are editorial roles, not status assignments. `surface-raised` adds a brighter surface per theme; `selection` supplies a text-selection field.

Generated theme aliases `--cc-shadow-raised` and `--cc-shadow-floating` reference the appropriate elevation or dark-elevation scale. Keep elevation separate from control focus. The schema version stays 1.0.0 because the JSON structure is unchanged; the release version is 1.1.0.
